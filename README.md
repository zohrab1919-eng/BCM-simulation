# BCM Simulation Game
**Enablerz Consulting & Solutions — Business Continuity Management Training Tool**

A real-time, browser-based, multiplayer BCM simulation for facilitated workshops.

---

## 1. QUICK START (run on the day)

```bash
npm install
npm start
```

Then open:
- **Host dashboard:** http://localhost:3000/host
- **Participant join:** http://localhost:3000/join
- **Leaderboard (projector):** http://localhost:3000/leaderboard

Share the participant URL or project the QR code from the host dashboard.

---

## 2. NETWORK SETUP

### Option A — Everyone on the same WiFi
Find your laptop's local IP, then share: `http://[YOUR-IP]:3000/join`

**Windows:** Open Command Prompt → type `ipconfig` → look for **IPv4 Address**
**Mac:** System Settings → Network → your connection → IP Address

### Option B — Mixed networks / public WiFi (recommended for workshops)
Deploy to a public URL so participants can join from any network or mobile data.
See Section 3 below.

---

## 3. FREE PUBLIC DEPLOYMENT (Railway — ~10 minutes)

1. Push this folder to a GitHub repository
2. Go to [railway.app](https://railway.app) and sign in with GitHub
3. Click **New Project → Deploy from GitHub repo** → select your repo
4. Railway auto-detects Node.js and runs `npm start`
5. Click **Settings → Domains → Generate Domain** to get a public URL
6. Set the `BASE_URL` environment variable to your Railway domain  
   e.g. `BASE_URL=https://bcm-simulation-production.up.railway.app`
7. Your QR codes and join links will use this URL automatically

**Cost:** Free tier is sufficient for workshop use (up to ~500 hours/month).

## 4. ADDING NEW SCENARIOS

All scenario content lives in `server/data/scenario_database.json`. No code changes needed.

**Minimal structure to add a new industry:**
```json
{
  "id": "HLT",
  "name": "Healthcare & Pharmaceuticals",
  "archetype": "Patient safety-critical, heavily regulated",
  "sub_types": ["Hospitals", "Clinics", "Pharma"],
  "archetype_modifiers": {
    "startup":    { "war_chest_multiplier": 0.6, "escalation_speed": 1.3, "regulatory_penalty_multiplier": 1.2 },
    "mid_market": { "war_chest_multiplier": 1.0, "escalation_speed": 1.0, "regulatory_penalty_multiplier": 1.0 },
    "enterprise": { "war_chest_multiplier": 1.7, "escalation_speed": 0.9, "regulatory_penalty_multiplier": 1.3 }
  },
  "war_chest_base": { "small": 400000, "medium": 1200000, "large": 3500000 },
  "default_departments": ["Clinical Operations", "Pharmacy", "IT & Health Informatics", "Compliance & Risk", "Corporate Communications / PR", "HR & Administration"],
  "scenarios": [
    {
      "id": "HLT-01",
      "name": "Patient Data Breach",
      "severity": "Critical",
      "probability_weight": 3,
      "regulatory_flag": true,
      "reputation_flag": true,
      "war_chest_impact_label": "RM 2–5M in fines and remediation",
      "trigger_text": "Your EMR system has been breached...",
      "threat_summary": "Patient records exposed — PDPA and MOH obligations triggered.",
      "escalation_waves": [ ... ],
      "recovery_levers": [ ... ],
      "debrief_notes": "Key lesson: ...",
      "debrief_template": "BIA_Financial_Services"
    }
  ]
}
```

Restart the server after saving. The app loads the JSON at runtime.

## 5. CUSTOMISING BRANDING

**Colours** — edit CSS variables at the top of each stylesheet:
- `client/host/host.css` — host dashboard
- `client/participant/participant.css` — participant screen

Key variables:
```css
--navy: #1B3A5C;   /* background */
--teal: #1A7A6E;   /* primary accent */
--amber: #E8A020;  /* highlight / war chest */
```

**Logo** — place your logo file (e.g. `enablerz-logo.png`) in `client/` and reference it in the HTML headers.

**Document footer** — edit the `BRAND` object at the top of `server/templateGenerator.js`:
```js
const BRAND = {
  name: 'Enablerz Consulting & Solutions',
  footer: 'Generated by Enablerz BCM Simulation',
  ...
};
```

## Architecture

```
bcm-simulation/
├── server/
│   ├── index.js              # Express + Socket.io server
│   ├── gameEngine.js         # All game logic and scoring
│   ├── templateGenerator.js  # Post-game DOCX + ZIP generation
│   └── data/
│       └── scenario_database.json
├── client/
│   ├── host/                 # Host dashboard
│   ├── participant/          # Participant game screen (mobile-first)
│   └── leaderboard/          # Projector leaderboard view
├── shared/
│   └── constants.js          # Shared game constants
└── package.json
```

**Stack:** Node.js 18+, Express, Socket.io, docx, qrcode, archiver  
**Storage:** In-memory only — no database required  
**Sessions expire:** 4 hours after creation
